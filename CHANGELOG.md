# Changelog

All notable changes to Peach will be documented in this file.

## Unreleased

### New Features

- **"Define format..." dialog for text-log sources** — builds a text-parser TOML config interactively instead of hand-editing it: the same fields (regex, timestamp format, multiline start pattern, assume offset, level/message capture groups), plus a live preview against the first 20 lines of the actual picked source file. Each preview line shows its named capture groups colour-highlighted and the exact level/message/timestamp a real load would produce (or its exact error) — the preview calls the same parsing code a real load does, so it can't show something a load would then contradict. Configs save to a per-user library (`Save`/`Save & Use`/`Load`), stored as the same TOML shape the text parser already reads, so there's no separate "profile" format to keep in sync.
- **Per-source visibility, and Level/Tag/Sources as dropdowns instead of always-visible button rows** — a new **Sources** dropdown (next to Level/Tag) lists every loaded source with a checkbox; unchecking one hides that source's rows from the timeline without unloading it. Backed by a new `source_id=` search-grammar field (exact match against the internal id of one specific load, not its path — so two independent loads of the same file, or a path containing spaces, both work correctly) and independent `NOT source_id=<id>` terms per hidden source, which the grammar's ordinary `AND` fold already combines correctly with no special-casing needed. Level and Tag are now dropdowns too (`Level (2)`/`Tag (5)`-style buttons opening a scrollable checklist) rather than a row of buttons that grew with every distinct value — a rule pack's worth of tags (33, for AUL's built-in pack) or many loaded sources no longer pushes the timeline down the screen. Every dropdown, consistently, has an **only** button per row (narrows to just that one value) and a **Show all** button that clears the whole selection, both pinned outside the scrollable list — "Show all" specifically never as the list's last scrolled item — so they stay reachable without scrolling all the way down first, which is exactly when they're most needed.
- **Per-value event counts in the Level/Tag/Sources dropdowns** — each checkbox now shows how many events carry that value (e.g. `wifi_status (1234)`), backed by three new narrow-column `GROUP BY` queries (`tag_value`/`level`/`source_file_id` only, never the wide `fields`/`raw` columns) refreshed on the same load/re-tag cadence as the dropdowns' own value lists. Deliberately a whole-loaded-timeline snapshot, not a live count of what the current search matches — a caption at the top of every dropdown says so explicitly, since a bare number next to a checkbox would otherwise read as "how many match right now" by default.
- **Time range picker** — a calendar-and-clock way to set `after=`/`before=` instead of typing an ISO timestamp: check After and/or Before, pick a date, adjust the hour/minute/second spinners next to it if needed (defaults to midnight for After, the last second of the day for Before), **Apply**. Both bounds always write the explicit `<date>T<hour>:<minute>:<second>` form, never a bare date — a bare date means literal midnight, which as a *before* bound with the time left untouched would otherwise silently exclude the rest of that day. Uses `egui_extras`'s `DatePickerButton` (new `datepicker` feature flag, no new dependency — already had `jiff`) plus plain `egui::DragValue` spinners, opened from a button as its own window rather than nested in a dropdown popup like Level/Tag/Sources — `DatePickerButton` opens its own independent floating popup with no awareness of an enclosing one, so nesting it inside a `menu_button` dropdown made the outer popup close the instant a date was clicked, before it could ever be picked.
- **Per-column filter chips** — the row context menu gained a **Filter by...** submenu listing whichever of the clicked row's Sourcetype/Host/Process/Event ID/Subsystem/Category are actually populated; picking one adds an exact-match filter shown as a removable chip in a new **Active filters** row under the search box (with a **Clear all** once more than one is active). These six fields had no dedicated dropdown the way Level/Tag/Sources do — a single loaded EVTX/journald source alone can have far too many distinct hostnames/process names for a checklist to make sense, so "pick from what this row already shows you" fits better than "pick from every value up front". Values containing whitespace (a process name, a hostname) are quoted (`process="Windows Explorer"`) so they round-trip correctly through the query grammar — the first place in `filter_bar.rs` that needed real tokenizer-aware quoting rather than the simpler whitespace-free values (Level/Tag/`source_id`/dates) every other row could get away without it.
- **Activity Log** (View menu) — every load and re-tag this session has run, persisted in the session `.sqlite` alongside tags/notes so it survives closing and reopening Peach: start/end time, status, and (on success) a summary line, a per-file entries-inserted breakdown for a multi-file load, and a per-rule tags-applied breakdown (keyed by rule *name*, not tag value — several rules can deliberately share one, e.g. EVTX's group-membership-change rules). Recorded on both success and failure, so a failed load doesn't just vanish once its error message is dismissed. Updates live if left open across a load/re-tag.
- **Built-in EVTX tagging rule pack** (`rules/examples/evtx_*.toml`) — 15 rules, one per Security-Auditing event ID already covered by the built-in message templates (logon/logoff, process creation, service install, account/group management, credential validation), each cross-checked against Microsoft's official event reference. Along the way, fixed a real gap in `Rule::matches`: `event_id`/`provider` conditions (exactly CLAUDE.md's own documented rule example) never actually matched an EVTX entry before this, because the generic match fallback only checks flat top-level `fields` keys, and EVTX nests both under `Event.System.*` — they're now resolved via the same sourcetype-aware JSON path the search bar's `event_id=` filter already used.
- **Per-rule built-in rule picker** — the old all-or-nothing "Built-in AUL rules"/"Built-in EVTX rules" checkboxes are now one **Built-in rules...** button opening a picker with every built-in rule (AUL and EVTX, in their own sections) as its own checkbox — hover one for its full match condition, tag, and description — plus **Select all**/**Select none** per section. Every rule enabled by default, same as before, but now exact per-rule control instead of only "the whole pack". Doubles as an in-app rule reference.
- **`docs/rules-reference.md`** — a browsable table of every built-in rule (match condition, tag, description), generated from the actual `rules/examples/*.toml` files (`scripts/gen_rules_reference.py`) rather than hand-transcribed, so it can't drift from what's shipped.
- **"Tag all matching (advanced)" can now match on any extracted field, not just message** — radio buttons at the top of the dialog let you pick **Message contains** (a substring) or an exact match on one of the clicked row's own populated fields (Sourcetype/Host/Process/Event ID/Subsystem/Category — the same set "Filter by..." offers), each with its own live match-count preview. A field condition always creates a fresh rule file rather than offering to extend an existing one — the tagging engine has no OR-list support for exact-match fields the way `message_contains` has. Along the way, extended `Rule::matches`'s sourcetype-aware field resolution (previously only `event_id`/`provider`) to also cover `host`/`subsystem`/`process`: EVTX's Host/Subsystem and journald's Host/Process are nested or differently-named in the underlying `fields` JSON the same way `event_id`/`provider` were, so a rule condition on those would otherwise have silently never matched real data.
- **Configurable rules directory, with auto-loading** (Settings) — where new rule files created via "Tag all matching (advanced)..." get written, same override-or-OS-default shape as the existing sessions directory setting. Point it at a folder under your own git repo to build a personal rule collection over time, kept separate from the read-only `rules/examples/` reference library shipped in the Peach repo. Every `*.toml` directly in this folder now loads automatically on startup, same as the built-in AUL/EVTX packs — a rule created in a previous session applies again without manually re-selecting it via "Choose tagging rules...", which itself now opens in this folder by default. Saving a changed rules directory re-scans and applies it immediately (replacing the current selection, the same way that button's own picker always has — not a merge). Both this and the sessions directory setting now always show the effective path in full (prefixed `(default)` rather than replaced by it, so the actual location is visible either way) alongside a new **Open folder** button that reveals it in the OS file manager, reusing the same cross-platform Explorer/Finder/`xdg-open` logic the "Manage sessions" dialog's own per-session **Open folder** already had (now shared via `ui::reveal` instead of living only in `session_dialog.rs`).
- **Abort button for a running load** — stops after the file currently being parsed finishes (or, for one very large file, at the next 10,000-entry checkpoint); whatever's already been inserted stays, nothing gets rolled back. Shows as **"Aborted"** with the real partial counts, recorded in the Activity Log as a new `cancelled` status (distinct from `ok`/`failed`) rather than looking like either a normal completion or a real error. A `--add-source`/multi-select queue does not auto-continue into its next file after an abort. The trickiest part was avoiding orphaned data: a file cancelled mid-parse still gets a proper `sources` row for whatever was flushed before the cutoff, by capturing the `source_file_id` off the first streamed entry rather than only from the (on this path, never-reached) success return value.
- **Every dialog is now a real, independent OS window** — About, Settings, Notes, Tag this event/Advanced tagging, View raw/fields, Define format, Manage sessions, and Time range can all now be dragged anywhere on the desktop, including onto a second monitor, instead of being confined to the main window the way a plain `egui::Window` always was (the pixels for an in-app popup simply don't exist outside the OS window it's drawn in — no drag-distance trick changes that). Built on egui's multi-viewport support (`Context::show_viewport_immediate`), which `eframe`'s native backend already enables by default on Linux/macOS/Windows, so no new dependency or app configuration was needed. One shared helper (`ui::dialog_window::show_dialog_window`) now backs all eight dialogs — including "View raw/fields", which already did this by hand before the rest — so window chrome and close-detection (the OS title bar's close button counts the same as an in-dialog Cancel/Close button) behave identically everywhere instead of each dialog reimplementing it slightly differently.

### Bug Fixes

- **Adding/editing a note or a manual analyst tag briefly re-filtered the whole timeline** — both went through the same path as a load/re-tag finishing (a full DuckDB recount, showing "Filtering…"), even though notes and analyst tags live entirely in the separate SQLite session DB and never change what a filter matches. A new `TimelineView::refresh_window()` now only drops the cached window (so the edit shows up immediately) without recounting.
- **Notes never showed on hover — only the 📝 marker in the Tags column was visible** — the row's right-click-context-menu widget is created after every per-cell widget in that row, and egui only reports the topmost click-sensing widget under the pointer as hovered, so the Tags/Notes cells' own `.on_hover_text()` silently never fired. The notes tooltip is now attached to the row-spanning widget itself, the only one in the row actually eligible to register hover.
- **Closing the "Choose .evtx/.journal/log file(s)..." picker via the window's own X button (instead of Cancel) crashed the whole app with an index-out-of-bounds panic** — on Linux, that interaction has been observed to resolve the picker to `Some(vec![])` rather than the documented `None`, and the handler unconditionally indexed `picked[0]`. Now treated the same as a cancelled dialog.
- **The Activity Log window's "Close" button could render below the visible window area** — its unbounded `ScrollArea` claimed all remaining vertical space before the button got a chance to, for any entry list tall enough to need scrolling. The button is now pinned to a fixed bottom panel; the scroll area gets exactly what's left above it.

## v0.1.0 - 2026-08-14

First release — beta quality. Rudimentary AUL support (with a built-in
pattern-of-life tagging rule pack), plus EVTX, journald, and
TOML-configurable text log parsing, all on top of a Splunk-inspired
search/filter, three-mode tagging engine, session persistence, CSV/JSON
export, and CLI handoff from crush
(`--add-source`/`--cleanup-dir`/`--ephemeral-session`). See
[docs/supported-sources.md](docs/supported-sources.md) for exactly what each
sourcetype does and doesn't cover today.

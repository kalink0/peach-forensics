# Changelog

All notable changes to Peach will be documented in this file.

## Unreleased

### New Features

- **"Define format..." dialog for text-log sources** — builds a text-parser TOML config interactively instead of hand-editing it: the same fields (regex, timestamp format, multiline start pattern, assume offset, level/message capture groups), plus a live preview against the first 20 lines of the actual picked source file. Each preview line shows its named capture groups colour-highlighted and the exact level/message/timestamp a real load would produce (or its exact error) — the preview calls the same parsing code a real load does, so it can't show something a load would then contradict. Configs save to a per-user library (`Save`/`Save & Use`/`Load`), stored as the same TOML shape the text parser already reads, so there's no separate "profile" format to keep in sync.
- **Per-source visibility, and Level/Tag/Sources as dropdowns instead of always-visible button rows** — a new **Sources** dropdown (next to Level/Tag) lists every loaded source with a checkbox; unchecking one hides that source's rows from the timeline without unloading it. Backed by a new `source_id=` search-grammar field (exact match against the internal id of one specific load, not its path — so two independent loads of the same file, or a path containing spaces, both work correctly) and independent `NOT source_id=<id>` terms per hidden source, which the grammar's ordinary `AND` fold already combines correctly with no special-casing needed. Level and Tag are now dropdowns too (`Level (2)`/`Tag (5)`-style buttons opening a scrollable checklist) rather than a row of buttons that grew with every distinct value — a rule pack's worth of tags (33, for AUL's built-in pack) or many loaded sources no longer pushes the timeline down the screen. Every dropdown, consistently, has an **only** button per row (narrows to just that one value) and a **Show all** button that clears the whole selection, both pinned outside the scrollable list — "Show all" specifically never as the list's last scrolled item — so they stay reachable without scrolling all the way down first, which is exactly when they're most needed.
- **Per-value event counts in the Level/Tag/Sources dropdowns** — each checkbox now shows how many events carry that value (e.g. `wifi_status (1234)`), backed by three new narrow-column `GROUP BY` queries (`tag_value`/`level`/`source_file_id` only, never the wide `fields`/`raw` columns) refreshed on the same load/re-tag cadence as the dropdowns' own value lists. Deliberately a whole-loaded-timeline snapshot, not a live count of what the current search matches — a caption at the top of every dropdown says so explicitly, since a bare number next to a checkbox would otherwise read as "how many match right now" by default.
- **Time range picker** — a calendar-and-clock way to set `after=`/`before=` instead of typing an ISO timestamp: check After and/or Before, pick a date, adjust the hour/minute/second spinners next to it if needed (defaults to midnight for After, the last second of the day for Before), **Apply**. Both bounds always write the explicit `<date>T<hour>:<minute>:<second>` form, never a bare date — a bare date means literal midnight, which as a *before* bound with the time left untouched would otherwise silently exclude the rest of that day. Uses `egui_extras`'s `DatePickerButton` (new `datepicker` feature flag, no new dependency — already had `jiff`) plus plain `egui::DragValue` spinners, opened from a button as its own window rather than nested in a dropdown popup like Level/Tag/Sources — `DatePickerButton` opens its own independent floating popup with no awareness of an enclosing one, so nesting it inside a `menu_button` dropdown made the outer popup close the instant a date was clicked, before it could ever be picked.
- **Per-column filter chips** — the row context menu gained a **Filter by...** submenu listing whichever of the clicked row's Sourcetype/Host/Process/Event ID/Subsystem/Category are actually populated; picking one adds an exact-match filter shown as a removable chip in a new **Active filters** row under the search box (with a **Clear all** once more than one is active). These six fields had no dedicated dropdown the way Level/Tag/Sources do — a single loaded EVTX/journald source alone can have far too many distinct hostnames/process names for a checklist to make sense, so "pick from what this row already shows you" fits better than "pick from every value up front". Values containing whitespace (a process name, a hostname) are quoted (`process="Windows Explorer"`) so they round-trip correctly through the query grammar — the first place in `filter_bar.rs` that needed real tokenizer-aware quoting rather than the simpler whitespace-free values (Level/Tag/`source_id`/dates) every other row could get away without it.
- **Activity Log** (View menu) — every load and re-tag this session has run, persisted in the session `.sqlite` alongside tags/notes so it survives closing and reopening Peach: start/end time, status, and (on success) a summary line, a per-file entries-inserted breakdown for a multi-file load, and a per-rule tags-applied breakdown (keyed by rule *name*, not tag value — several rules can deliberately share one, e.g. EVTX's group-membership-change rules). Recorded on both success and failure, so a failed load doesn't just vanish once its error message is dismissed. Updates live if left open across a load/re-tag.
- **Built-in EVTX tagging rule pack** (`rules/examples/evtx_*.toml`) — now 25 rules (was 15), one per Security-Auditing event ID already covered by the built-in message templates or otherwise high forensic value (logon/logoff, process creation, service install, account/group lifecycle — create/enable/disable/delete/lock/unlock, self vs. admin password changes, credential validation, scheduled task creation/deletion, RDP session reconnect/disconnect, and the audit log being cleared), each cross-checked against Microsoft's official event reference. Along the way, fixed a real gap in `Rule::matches`: `event_id`/`provider` conditions (exactly CLAUDE.md's own documented rule example) never actually matched an EVTX entry before this, because the generic match fallback only checks flat top-level `fields` keys, and EVTX nests both under `Event.System.*` — they're now resolved via the same sourcetype-aware JSON path the search bar's `event_id=` filter already used.
- **Built-in journald tagging rule pack** (`rules/examples/journald_*.toml`) — 12 rules, journald's first (was previously the only sourcetype with none): SSH logon success/failure/logoff, sudo command usage/denial, privilege escalation via `su`, password changes, and account lifecycle (created/deleted/locked-unlocked/modified) and group membership changes via `useradd`/`userdel`/`usermod`. Message text sourced directly from OpenSSH, sudo, and shadow-utils' own logging code, not re-derived from memory. Each rule scopes itself to a specific `process` (journald's `SYSLOG_IDENTIFIER`) as well as `sourcetype = "journald"`, since journald's message text is the only signal available (unlike EVTX's structured `event_id`) and several daemons could otherwise share a substring. One real substring-collision caught along the way: `usermod`'s `"lock user '..."`/`"unlock user '..."` messages can't be told apart with plain substring matching (`"lock user '"` is itself a substring of `"unlock user '..."`), so both map to one `account_lock_state_changed` tag rather than shipping a rule that would silently mislabel every unlock as a lock.
- **AUL rule pack extended** (now 37 rules, was 33) — 4 new rules plus 2 existing ones extended, sourced from Tim Korver's [Thesis Friday](https://thesisfriday.com/) series rather than the existing iLEAPP-derived predicates: **`aul_dialed_number_recovery`** (new, high-value — `CommCenter`'s call-provider subsystem logs a dialed number in plain text via `kPhoneNumber`, a more direct signal than `aul_call_events`' existing keypad-tone-actionID reconstruction, kept as a separate tag on purpose), **`aul_device_orientation`** (new — portrait/landscape/face up-down transitions), **`aul_watch_crown_button`** (new, watchOS-only — Digital Crown/side button presses), **`aul_carplay_connection`** (new — CarPlay accessory handshake, CarKit session auth, per-vehicle widget state, continuing on from the already-covered generic USB-connect step). `aul_airplane_mode` gained the `"isAirplaneMode = 0/1"` predicate actually seen on iOS 26 beta (older predicates alone would silently miss the mainstream current-OS variant); `aul_biometric_sensor_events` gained `"setFingerOnState: FingerON"`, the macOS Touch ID sensor stack's own predicate (distinct from the existing iOS home-button ones). Six other candidate articles from the same series (Mail app launch, volume buttons, USB connect, older-iOS airplane mode, Emergency SOS cross-device handshake) were checked and found to already be covered by existing rules' predicates — not duplicated.
- **EVTX/journald rule packs extended with more IR-focused signals** (EVTX now 35, was 25; journald now 15, was 12) — sourced from JPCERT/CC's "Detecting Lateral Movement through Tracking Event Logs" report, the `awesome-event-ids` reference, and Microsoft's own docs. EVTX gained: **4104** (PowerShell Script Block Logging — the actual, de-obfuscated code executed; different channel than the rest of this pack, `Microsoft-Windows-PowerShell/Operational`, which `event_id` matching handles transparently), **4689** (process exited, 4688's natural pair), **4768**/**4769** (Kerberos TGT/service ticket requested, domain-controller-only — base signal for Kerberoasting/Golden Ticket detection), **5145** (SMB share access check — lateral-movement/tool-transfer visibility), **7045** (service installed, from the System log/Service Control Manager rather than Security — unlike the existing `evtx_service_install` (4697), not gated behind a non-default audit subcategory, shares that rule's tag), and a reboot/shutdown quartet — **6005** (boot), **6008**+**41** (unexpected/dirty shutdown, System log and Kernel-Power's own signal, one shared tag), **1074** (requested shutdown/restart, with requestor). journald gained **cron** job execution (`"CMD ("`, two rules for cronie's `CROND` vs. Debian/Ubuntu's `CRON` syslog identifiers, one shared tag) and a **kernel boot marker** (`"Linux version"`, the first ring-buffer line of every boot, matched via the `_TRANSPORT=kernel` trusted journal field rather than an unreliable `SYSLOG_IDENTIFIER` guess) — sharing its `system_boot` tag with EVTX's own boot marker across sourcetypes. Sysmon-based detections from the same JPCERT report were deliberately left out: Sysmon is a separately-installed tool, not a Windows default, so a rule for it would silently never match most real EVTX exports.
- **Per-rule built-in rule picker** — the old all-or-nothing "Built-in AUL rules"/"Built-in EVTX rules" checkboxes are now one **Built-in rules...** button opening a picker with every built-in rule (AUL and EVTX, in their own sections) as its own checkbox — hover one for its full match condition, tag, and description — plus **Select all**/**Select none** per section. Every rule enabled by default, same as before, but now exact per-rule control instead of only "the whole pack". Doubles as an in-app rule reference.
- **Help > Rules reference...** — shows the full `docs/rules-reference.md` table (every built-in AUL/EVTX/journald rule's match condition, tag, and description) in its own window, with a filter field for jumping to a rule/tag by name. Embedded into the binary at compile time (`include_str!`) rather than opened as a link — a lot of DFIR work happens on airgapped analysis machines with no internet access at all, and Peach is explicitly a local-only tool already (no cloud sync, no server), so requiring a browser and network access just to read documentation about an otherwise fully-offline feature was the odd one out. A **Open on GitHub...** button inside the dialog still offers the nicely-rendered table for whoever has connectivity. `<br>`/`&bull;` (used in the source so GitHub renders bullet lists inside table cells) are converted to a real newline/bullet for the monospace display — everything else (table pipes, `**bold**`, markdown links) passes through as plain text rather than pulling in a full markdown-rendering dependency for what's ultimately a reference table. README's own Documentation list also gained a mention of the in-app copy (it already linked the file itself).
- **`docs/rules-reference.md`** — a browsable table of every built-in rule (match condition, tag, description), generated from the actual `rules/examples/*.toml` files (`scripts/gen_rules_reference.py`) rather than hand-transcribed, so it can't drift from what's shipped.
- **"Tag all matching (advanced)" can now match on any extracted field, not just message** — radio buttons at the top of the dialog let you pick **Message contains** (a substring) or an exact match on one of the clicked row's own populated fields (Sourcetype/Host/Process/Event ID/Subsystem/Category — the same set "Filter by..." offers), each with its own live match-count preview. A field condition always creates a fresh rule file rather than offering to extend an existing one — the tagging engine has no OR-list support for exact-match fields the way `message_contains` has. Along the way, extended `Rule::matches`'s sourcetype-aware field resolution (previously only `event_id`/`provider`) to also cover `host`/`subsystem`/`process`: EVTX's Host/Subsystem and journald's Host/Process are nested or differently-named in the underlying `fields` JSON the same way `event_id`/`provider` were, so a rule condition on those would otherwise have silently never matched real data.
- **Configurable rules directory, with auto-loading** (Settings) — where new rule files created via "Tag all matching (advanced)..." get written, same override-or-OS-default shape as the existing sessions directory setting. Point it at a folder under your own git repo to build a personal rule collection over time, kept separate from the read-only `rules/examples/` reference library shipped in the Peach repo. Every `*.toml` directly in this folder now loads automatically on startup, same as the built-in AUL/EVTX packs — a rule created in a previous session applies again without manually re-selecting it via "Choose tagging rules...", which itself now opens in this folder by default. Saving a changed rules directory re-scans and applies it immediately (replacing the current selection, the same way that button's own picker always has — not a merge). Both this and the sessions directory setting now always show the effective path in full (prefixed `(default)` rather than replaced by it, so the actual location is visible either way) alongside a new **Open folder** button that reveals it in the OS file manager, reusing the same cross-platform Explorer/Finder/`xdg-open` logic the "Manage sessions" dialog's own per-session **Open folder** already had (now shared via `ui::reveal` instead of living only in `session_dialog.rs`).
- **Abort button for a running load** — stops after the file currently being parsed finishes (or, for one very large file, at the next 10,000-entry checkpoint); whatever's already been inserted stays, nothing gets rolled back. Shows as **"Aborted"** with the real partial counts, recorded in the Activity Log as a new `cancelled` status (distinct from `ok`/`failed`) rather than looking like either a normal completion or a real error. A `--add-source`/multi-select queue does not auto-continue into its next file after an abort. The trickiest part was avoiding orphaned data: a file cancelled mid-parse still gets a proper `sources` row for whatever was flushed before the cutoff, by capturing the `source_file_id` off the first streamed entry rather than only from the (on this path, never-reached) success return value.
- **Every dialog is now a real, independent OS window** — About, Settings, Notes, Tag this event/Advanced tagging, View raw/fields, Define format, Manage sessions, and Time range can all now be dragged anywhere on the desktop, including onto a second monitor, instead of being confined to the main window the way a plain `egui::Window` always was (the pixels for an in-app popup simply don't exist outside the OS window it's drawn in — no drag-distance trick changes that). Built on egui's multi-viewport support (`Context::show_viewport_immediate`), which `eframe`'s native backend already enables by default on Linux/macOS/Windows, so no new dependency or app configuration was needed. One shared helper (`ui::dialog_window::show_dialog_window`) now backs all eight dialogs — including "View raw/fields", which already did this by hand before the rest — so window chrome and close-detection (the OS title bar's close button counts the same as an in-dialog Cancel/Close button) behave identically everywhere instead of each dialog reimplementing it slightly differently.
- **App icon** — Peach's window now shows the starfish icon instead of the generic default. Embedded as a pre-rasterized raw RGBA buffer (`resources/icons/peach_icon_256.rgba`, generated once from the SVG via `rsvg-convert`+`magick`) rather than decoded from a compressed format at startup, so no new image-decoding dependency was needed for the running window's own icon (`egui::ViewportBuilder::with_icon`). That mechanism turned out to be a no-op on Wayland and on macOS — both platforms only take an app's icon from something set at *build/packaging* time (a `.desktop` file + icon theme entry on Wayland, an `.app` bundle's `.icns` on macOS), not anything an app can set on itself at runtime; confirmed directly from `winit`'s own per-platform `set_window_icon` implementations. **Windows** doesn't have that limitation, so it additionally now gets the `.exe` itself embedded with a proper multi-resolution icon (`resources/windows/peach.ico`: 16/32/48/256px, via a new `build.rs` step using the `winresource` crate, Windows-only build-dependency) — shows in Explorer, the taskbar, and Alt-Tab even before Peach is running, not just once a window exists. The equivalent for Wayland (`.desktop` file) and macOS (`.app` bundle + `.icns`, which would also mean changing `release.yml`'s packaging step away from shipping a bare binary) are deliberately not done yet — separate, bigger changes, out of scope for this pass.
- **Built-in text-log format library** (`parsers/examples/*.toml`) — a small starter set for `Text (config-based)` sources, inspired by crush's own multi-log viewer's built-in format detection (Generic/Syslog/Logcat/JSON Lines): Generic timestamp (`YYYY-MM-DD HH:MM:SS`, the shape most hand-rolled application logs use — a plain, human-readable log that starts with a date/time previously needed a hand-written TOML with no starting point at all), Syslog (RFC 3164), Android Logcat (brief format), and Pacman log (`/var/log/pacman.log` on Arch/Manjaro/EndeavourOS — `[ISO8601 timestamp] [CATEGORY] message`, confirmed against both a real pacman.log and libalpm's own log-line format; its timestamp already carries an explicit offset and year, so unlike syslog/logcat neither `assume_offset` nor `assume_year` is ever needed for it). Picked from a new **Built-in formats** dropdown in "Define format...", loading straight into the same fields/live-preview flow as the analyst's own saved configs — not an auto-detector that applies itself blindly, since a real log's exact shape varies too much for that (and unlike crush's Python implementation, which papers over this with `datetime.now().year` at parse time, Peach's TOML-config model has no way to inject a value that doesn't come from either the log line or the config, so both `assume_offset` and, for syslog/logcat specifically, `assume_year` are deliberately left blank in the shipped starters rather than guessed). Embedded via the same `build.rs` mechanism as the tagging rule packs, so these work in a release build with no repo checkout nearby, same as those.
- **`assume_year` config field** for text-log sources — same "explicit per-source override, never a silent guess" shape as the existing `assume_offset`, for when `timestamp_format` doesn't carry a year at all (classic BSD syslog and Android logcat's brief format both genuinely never do — confirmed directly against `chrono`: parsing a year-less format with no way to supply one afterward fails outright with "input is not enough for unique date and time"). Required rewriting `parse_timestamp` on `chrono::format`'s lower-level `Parsed` API instead of the `DateTime`/`NaiveDateTime::parse_from_str` convenience functions, which have no way to fill in a field after the fact.
- **Timezone settings** — two new, independent fields, both accepting a fixed offset (`+0100`/`+02:00`/`UTC`, colon optional) or a real IANA zone name (`Europe/Berlin`, new `chrono-tz` dependency) so DST resolves correctly across a case spanning a transition, unlike a fixed offset. **Assume timezone for logs with no timezone of their own** is a session-wide fallback for a text source's per-source `assume_offset`, used only when that source's own config doesn't set one (its own setting always wins) — resolved once by `app::run_load` and passed into `TextConfigParser` as a field, keeping the parser itself settings-agnostic; editable both in Settings and, since the setting matters most right when about to load one, directly in the load controls once `Text (config-based)` is selected (same field, applies and saves immediately either place). **Display timezone** controls what the timeline table and CSV/JSON export render timestamps in; blank means UTC, same as every display before this setting existed. Purely a display concern: `log_entries.timestamp_utc` and every internal UTC-based mechanism (the "Show context around this event" query, sorting) are completely unaffected — `DisplayRow`/`FullEntry` gained a separate `timestamp_display` field alongside the untouched `timestamp_utc` rather than repurposing it. Every rendered/exported value always carries its own offset suffix (`TimezoneSpec::format_utc`, e.g. `2026-07-28 14:00:00.000 +02:00`) regardless of which zone is configured, so a value stays unambiguous on its own even if the setting changes later or an export outlives the session that produced it — the exported CSV/JSON column was renamed from `timestamp_utc` to `timestamp` to match. Set from a new **View > Display timezone...** window rather than Settings — unlike the load-controls field above, View is reachable regardless of what's currently loaded/selected, so there was no reason to also put it in Settings. Both fields validate as you type; an invalid value shows an error and never gets applied.
- **Settings dialog: long explanatory paragraphs collapsed behind a "?" button** next to each setting's label — the dialog had grown into a wall of always-visible text as more settings were added; the actual controls are now the visually dominant thing, with the full rationale a click away rather than removed. Toggled by click (persisted per-row via `egui::Context::data`), not hover-only: a tooltip on a tiny single-character button turned out easy to miss entirely (hold the pointer still, wait out the tooltip delay, over a small target) — clicking is unambiguous and the explanation stays on screen until clicked again, as its own line under the row, rather than only for as long as the pointer happens to stay put. Still also shows on hover for anyone who finds that first.

### Bug Fixes

- **Adding/editing a note or a manual analyst tag briefly re-filtered the whole timeline** — both went through the same path as a load/re-tag finishing (a full DuckDB recount, showing "Filtering…"), even though notes and analyst tags live entirely in the separate SQLite session DB and never change what a filter matches. A new `TimelineView::refresh_window()` now only drops the cached window (so the edit shows up immediately) without recounting.
- **Notes never showed on hover — only the 📝 marker in the Tags column was visible** — the row's right-click-context-menu widget is created after every per-cell widget in that row, and egui only reports the topmost click-sensing widget under the pointer as hovered, so the Tags/Notes cells' own `.on_hover_text()` silently never fired. The notes tooltip is now attached to the row-spanning widget itself, the only one in the row actually eligible to register hover.
- **Closing the "Choose .evtx/.journal/log file(s)..." picker via the window's own X button (instead of Cancel) crashed the whole app with an index-out-of-bounds panic** — on Linux, that interaction has been observed to resolve the picker to `Some(vec![])` rather than the documented `None`, and the handler unconditionally indexed `picked[0]`. Now treated the same as a cancelled dialog.
- **The Activity Log window's "Close" button could render below the visible window area** — its unbounded `ScrollArea` claimed all remaining vertical space before the button got a chance to, for any entry list tall enough to need scrolling. The button is now pinned to a fixed bottom panel; the scroll area gets exactly what's left above it.
- **"Define format..." window's Save/Save & Use/Cancel buttons could render below the visible window area** — same underlying issue as the Activity Log fix above: the form fields plus the live preview could add up to more than the window's default height, with no unbounded `ScrollArea` to blame this time (the preview already had its own bounded one) but nothing pinning the buttons in place either. The button row (and any save/load error message) is now pinned to a fixed bottom panel, and the form fields above it gained their own scroll area so they stay reachable even on a window too short for everything at once.

## v0.1.0 - 2026-08-14

First release — beta quality. Rudimentary AUL support (with a built-in
pattern-of-life tagging rule pack), plus EVTX, journald, and
TOML-configurable text log parsing, all on top of a Splunk-inspired
search/filter, three-mode tagging engine, session persistence, CSV/JSON
export, and CLI handoff from crush
(`--add-source`/`--cleanup-dir`/`--ephemeral-session`). See
[docs/supported-sources.md](docs/supported-sources.md) for exactly what each
sourcetype does and doesn't cover today.
